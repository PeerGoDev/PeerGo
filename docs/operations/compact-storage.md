# Tracker 存储减量与自动回收

本次改动减少重复、无效的存储写入，并修复清理候选仅存在于进程内存中的问题。
保留生产现有的最低时间窗：已完成消息和任务 3 小时，会话和明细 12 小时，异常证据 30 天。
长期累计流量继续保存在 `ledger.traffic_daily_rollups`；非零流量仍先按原规则结算，再累计结果。

## 零流量心跳

上传、下载原始增量都为零时，策略结算仍验证完整的规则覆盖，保留原始活动区间、会话基线、
去重游标、完成事件的 H&R 任务及必要的限速证据，但不写入流量结算、分段、流量 outbox 或日汇总。
因此 Core 不再收到这些全零流量投影。只要原始上传或下载非零，即使促销使计费结果为零，
仍按原来的规则生成完整账务证据；没有先合并流量再计费，不改变舍入方式。

## 消费完成后的自动回收

* 删除已发布流量 outbox 时，在同一个数据库事务中登记明细回收任务。
* 删除原始区间的依赖记录时，同事务登记原始区间回收任务。暂时受时间窗、其他依赖或 H&R
  保护的记录保留任务，5 分钟后重试。任务领取使用行锁和 `SKIP LOCKED`，删除失败整体回滚。
* 历史流量明细按 `(interval_ends_at, settlement_id)` 游标分批扫描，补登记已没有 outbox 的明细。
  尚未发布的消息保留；以后消息删除时由触发器登记，不受已前进的扫描游标影响。
* 历史原始区间按 `(ends_at, event_id)` 游标补登记，仅推进到现有证据闭合水位。
  未闭合的纯做种区间不额外堆积逐心跳任务，闭合后由此游标发现。
* 明细清理按已领取的 ID 查询，避免每次为寻找几千条候选而遍历全部账本。

这些步骤由现有 `storage-maintenance` 服务持续运行，无需再增加每日全表删除脚本。

## 全量 Swarm 快照减量

在 12 小时明细保留期之后，同一个 UTC 小时、同一个 `source_id/routing_epoch` 内的完整快照，
若前后都有完整帧且不位于整点，可以回收其冗余 entries。保留每小时第一帧、最后一帧、
整点帧，以及不同消费流的第一帧；已被证据窗口选中或作为 fence 的帧也受保护。
每批删除数量有限，最后一批结束后登记完成标记，避免反复探测已经清空的大快照。

即使旧小时因证据缺口尚未闭合，也能删除证明不可能成为未来小时边界样本的中间帧。
快照头、去重 inbox、chunk 的现有保护继续生效，异常窗口的选中证据仍保留。

## 迁移与验证

新增 Tracker 迁移 `202610160001_tracker_compact_storage.sql`，并同步 Settlement 和 Core
preflight 的预期迁移版本。sqlc 固定使用项目的 `v1.31.1`，生成物需一并发布。

验证命令：

```sh
cd services/settlement
GOWORK=off go test ./...
PEERGO_TEST_TRACKER_DATABASE_URL=postgres://.../disposable_tracker \
PEERGO_TEST_NATS_URL=nats://disposable-nats:4222 \
GOWORK=off go test -race -count=1 ./internal/settler
```

分别为 `ingest`、`settler`、`hnr`、`seedingevidence`、`storagecleanup` 使用独立、完整迁移过的
可丢弃数据库执行集成测试。不可把测试连接指向生产库：测试会追加不可变证据。
Core 另执行 `GOWORK=off go test ./cmd/preflight`，并检查 sqlc 重复生成一致性及时间参数规则。

新增回归覆盖零流量和零字节完成、缺失策略覆盖、重复投递、后续真实流量、快照小时边界、
跨路由和跨消费流、年轻快照保护、分批清理、事务回滚、重启重试、历史候选补登记、
延迟消息发布，以及零流量做种 600 秒在闭合后仍正确生成奖励证据。

正式发布前应保存可恢复备份，协调更新迁移和依赖该版本的进程。迁移拒绝向下回滚，
因为清理后的冗余 entries 无法通过 SQL Down 重建；恢复使用备份或向前修复。
常规 DELETE 后空间首先由 PostgreSQL 复用，不代表操作系统立即增加相同数量的可用空间。

## 仍需单独处理的部分

本次没有改写做种证据的摘要格式，也没有把全部原始活动区间合并成新账本。
未闭合小时需要的活动、正在跟踪的 H&R 和异常证据继续保留。
生产旧小时的快照覆盖缺口仍需要独立修复；不能通过推进闭合水位或写入虚构的零奖励窗口跳过。
因此这一批能减少零账务复制和冗余快照增长，不能单独保证所有存储从此不再增长。
