# Bounded evidence maintenance and activity reads

Closed evidence remains immutable and losslessly recoverable through the hot/packed read views. The existing pack function retains its 72-hour cutoff, transaction guard, per-user/hour boundary and maximum batch of 128 groups. Core now requests that existing maximum and retries after 10 seconds when packing progresses (previously 64 groups per 30 seconds). Each call still has a 10-second deadline. Other retention rules are unchanged. Actual throughput depends on group size and I/O; moving old rows into packs may temporarily grow files until freed hot pages are reused or separately reclaimed.

Retention contribution and newcomer assessment reads use an exact derived user/hour cache, then the existing pack summary, then an exact hot aggregate. Absence remains NULL, zero remains zero, UTC/full-hour boundaries and historical membership transitions remain authoritative. No eligibility, credits, reward or historical coverage is fabricated.

The cache only materializes hot groups requested by retention memberships (current/previous month) or active newcomer assessments. Completed windows populate these consumers; a bounded backfill handles older hot windows. Counts and sums are validated against immutable source items. Statement triggers invalidate affected cache keys on insert and delete; packing retires the cache in the same transaction. Missing cache rows always fall back to source data. The cache is disposable derived state and is revoked from PUBLIC. Production writes through the projector and maintenance serialize on the evidence window row. Do not directly populate it outside the guarded maintenance function/window lock.

Exact completed/dead reward counts use a deduplicated status index, and latest-error reads use a partial error index. The monitor preserves historical errors and exact totals without scanning every wide work row several times. Both indexes build concurrently.

Verification uses a network-isolated disposable PostgreSQL 18 container, all real migrations, rejected mutations, transaction rollback, lossless pack roundtrips, live append invalidation/completion, old/new monitor query equivalence and focused Go tests. Schema changes require all Core-starting binaries to carry the new schema contract. Keep independent Tracker control/snapshot publishers alive through combined worker replacement, confirm two fresh worker snapshots, remove helpers, and observe Tracker readiness for a full snapshot lifetime.

Storage reports must distinguish logical deletion, reusable table space, physical filesystem reclamation, persistent proof and protected recovery backups. Reindexing sparse indexes concurrently is independent of business row retention. Do not broaden unattended evidence cleanup or delete immutable inbox/journal history as disposable logs.
