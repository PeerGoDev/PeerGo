# Audit events v1

`decision-recorded.schema.json` is the reviewed wire contract for authorization enforcement decisions. `grant-revocation-recorded.schema.json` records proposals, independent reviews, conflicts, expiry and application using pseudonyms plus before/after hashes. `staff-credential-bootstrap-recorded.schema.json` links one-time operator ticket issuance to the resulting encrypted WebAuthn credential while hashing operator references, labels and credential IDs. `category-change-recorded.schema.json` records category creation and optimistic-concurrency updates with pseudonymized actors and hashed state/reasons. `announcement-change-recorded.schema.json` records draft, publication scheduling, cancellation, immediate publication and withdrawal transitions while keeping announcement prose and human reasons behind hashes. `torrent-review-recorded.schema.json` records one optimistic approve/reject transition with a stable public torrent ID, pseudonymized reviewer/uploader, stable reason code and hashed human explanation/state. `torrent-lifecycle-change-recorded.schema.json` records explicit disable/restore transitions, optimistic versions and Tracker eligibility state while keeping the human reason behind a digest. `comment-moderation-decision-recorded.schema.json` remains the historical torrent-only v1 contract; new decisions use the typed-target v2 contract in `../v2/`. `site-display-settings-change-recorded.schema.json` records the versioned low-risk site/display singleton update while keeping editable values and the human reason behind hashes. `registration-policy-change-recorded.schema.json` records the identity-owned admission-mode transition with monotonic versions, authorization evidence and hashed state/reason. `account-restriction-recorded.schema.json` records bounded account-access restriction creation and explicit revocation with pseudonymized actors/targets, monotonic versions and hashed human reasons/state. `registration-completed.schema.json` proves completion of the fail-closed registration saga using an opaque registration ID, admission mode and keyed user pseudonym, without direct identifiers or credential material. `email-verified.schema.json` records only an opaque verification ID and keyed user pseudonym. `password-recovered.schema.json` adds the opaque recovery ID, keyed user pseudonym and revoked-session count; email values, credential references, password material and token digests stay out of the audit stream. `two-factor-change-recorded.schema.json` records enable, recovery-code rotation and disable outcomes plus their session blast radius; it never contains the TOTP seed, recovery codes, password, credential reference or session identifier. Core owns the semantic payload; Audit Sink validates only the bounded envelope and stores the exact bytes so it does not duplicate domain types.

Delivery contract:

- `POST /internal/v1/audit/events` is service-authenticated and not part of the public OpenAPI surface.
- The body is the exact JSON event bytes committed to Core `audit.outbox`.
- `Idempotency-Key` equals `event_id`.
- `X-PeerGo-Content-SHA256` is the lowercase hexadecimal SHA-256 of the body.
- `201` means newly fsynced; `200` means the same ID and digest was already fsynced.
- Reusing an event ID with different bytes returns `409` and is never overwritten.
- Core marks an outbox row delivered only after `200/201`; a crash before that update intentionally causes an idempotent replay.

The local Audit Sink journal is a development/first-slice durability adapter. Its record hash chain detects mutation, reordering, gaps and incomplete writes in retained history. A production adapter must additionally anchor heads and stream immutable segments to versioned Object Lock/WORM storage; a local chain alone cannot prove that a complete suffix was not deleted.
